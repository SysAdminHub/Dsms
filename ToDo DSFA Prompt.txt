------------------------------------------------------------
1. Fachliches Ziel
------------------------------------------------------------

Das DSFA-Modul soll helfen, Datenschutz-Folgenabschätzungen strukturiert zu dokumentieren.

Eine DSFA soll dokumentieren:

- Für welche Verarbeitungstätigkeit die DSFA durchgeführt wird
- Warum eine DSFA erforderlich ist
- Welche Risiken für betroffene Personen bestehen
- Welche Maßnahmen zur Risikoreduzierung vorgesehen sind
- Wie hoch das verbleibende Restrisiko ist
- Ob die Verarbeitung freigegeben, abgelehnt oder weiter zu prüfen ist

------------------------------------------------------------
2. Datenmodell
------------------------------------------------------------

Erstelle ein neues Model für Datenschutz-Folgenabschätzungen.

Vorschlag für den technischen Namen:

- DataProtectionImpactAssessment
oder, falls das Projekt deutsche Begriffe nutzt:
- Dpia

Das Model soll mindestens folgende Felder enthalten:

- Id
- TenantId
- ProcessingActivityId
- Titel
- BeschreibungDerVerarbeitung
- GrundFuerDSFA
- NotwendigkeitUndVerhaeltnismaessigkeit
- BewertungDerRisiken
- Schutzmassnahmen
- Restrisiko
- Ergebnis
- Status
- VerantwortlichePerson
- PruefungDurch
- Pruefdatum
- NaechstePruefungAm
- CreatedAt
- UpdatedAt

Vorschlag für Status:

- Entwurf
- In Prüfung
- Freigegeben
- Abgelehnt
- Überarbeitung erforderlich
- Archiviert

Vorschlag für Restrisiko:

- Niedrig
- Mittel
- Hoch
- Kritisch
- Noch nicht bewertet

Vorschlag für Ergebnis:

- Verarbeitung zulässig
- Verarbeitung nur mit zusätzlichen Maßnahmen zulässig
- Verarbeitung aktuell nicht zulässig
- Beratung durch Datenschutzbeauftragten erforderlich
- Konsultation der Aufsichtsbehörde zu prüfen
- Noch nicht bewertet

Bitte verwende in der UI deutsche Bezeichnungen.

Technische Feldnamen im Code dürfen auf Englisch bleiben, wenn das zum bestehenden Projektstil passt.

------------------------------------------------------------
3. Beziehung zu Verarbeitungstätigkeiten
------------------------------------------------------------

Eine DSFA muss immer zu einer Verarbeitungstätigkeit gehören.

Setze eine Beziehung um:

- Eine Verarbeitungstätigkeit kann keine, eine oder mehrere DSFAs besitzen.

Empfehlung:
Nutze eine 1:n-Beziehung:

ProcessingActivity 1:n DataProtectionImpactAssessment

Grund:
So kann später eine neue DSFA-Version oder erneute Bewertung dokumentiert werden.

Wichtig:
Alle DSFAs müssen mandantenbezogen geschützt sein.
Eine DSFA darf nur mit einer Verarbeitungstätigkeit desselben Mandanten verknüpft werden.

------------------------------------------------------------
6. Integration in Verarbeitungstätigkeiten
------------------------------------------------------------

Ersetze den bisherigen DSFA-Platzhalter auf der Detailseite der Verarbeitungstätigkeit durch echte DSFA-Informationen.

Auf `/processing-activities/{Id}` soll im DSFA-Bereich angezeigt werden:

- DSFA erforderlich: Ja/Nein/Zu prüfen, falls Feld vorhanden
- Anzahl vorhandener DSFAs
- Status der neuesten DSFA
- Restrisiko der neuesten DSFA
- Ergebnis der neuesten DSFA
- Nächste Prüfung
- Link zur DSFA-Detailansicht
- Button „DSFA anlegen“, wenn der Benutzer Admin oder Auditor ist

Wenn `DpiaRequired` auf Ja steht, aber keine DSFA vorhanden ist, soll ein Warnhinweis angezeigt werden:

„DSFA erforderlich, aber noch keine DSFA angelegt.“

Wenn `DpiaRequired` auf Nein steht und keine DSFA vorhanden ist, soll kein kritischer Warnhinweis angezeigt werden.

Wenn `DpiaRequired` auf Zu prüfen oder unbekannt steht, soll ein Hinweis angezeigt werden:

„DSFA-Erforderlichkeit ist noch zu prüfen.“

9. Mandantentrennung und Sicherheit
------------------------------------------------------------

Alle Daten müssen sauber nach TenantId gefiltert werden.

Beachte insbesondere:

- DSFA-Liste darf nur DSFAs des aktuellen Mandanten anzeigen.
- DSFA-Detailseite darf nur DSFAs des aktuellen Mandanten anzeigen.
- DSFA-Bearbeitung darf nur für DSFAs des aktuellen Mandanten möglich sein.
- Verarbeitungstätigkeiten in Dropdowns dürfen nur aus dem aktuellen Mandanten stammen.
- Beim Speichern muss geprüft werden, dass die gewählte Verarbeitungstätigkeit zum aktuellen Mandanten gehört.
- Direkte URL-Manipulation darf nicht dazu führen, dass Daten anderer Mandanten angezeigt oder verändert werden.

Nicht nur die UI darf filtern.
Auch serverseitig beim Speichern muss geprüft werden, dass keine fremden IDs gespeichert werden.
